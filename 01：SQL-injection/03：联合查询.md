## 2. 联合查询是什么

`UNION` 可以把多个 `SELECT` 查询的结果合并到一起。

在 SQL 注入中，可以利用这一点，把自己想查询的内容拼接到原本的查询结果中，从而尝试获取数据库中的其他信息。MySQL 官方文档也说明，`UNION` 会将多个查询块的结果合并成一个结果集。

简单理解：

```sql
SELECT id,username FROM users
UNION
SELECT 1,2;
```

相当于把两个查询的结果放到一起。

------

## 3. 为什么要先判断列数

联合查询有一个关键条件：

> 两边 `SELECT` 的列数需要一致。

例如原查询有 3 列：

```sql
SELECT id,username,password FROM users
```

那么联合查询也需要对应 3 列：

```sql
UNION SELECT 1,2,3
```

如果列数不一致，通常会报错。不同查询中对应位置的数据类型也需要兼容。

------

## 4. 判断列数

我在参数后面尝试：

```sql
ORDER BY 1
ORDER BY 2
ORDER BY 3
```

不断增加数字。

如果：

```sql
ORDER BY 3
```

正常，而：

```sql
ORDER BY 4
```

报错，

说明当前查询结果大概率有 **3 列**。

也可以使用：

```sql
UNION SELECT NULL
UNION SELECT NULL,NULL
UNION SELECT NULL,NULL,NULL
```

逐渐增加列数进行判断。

## 6. 联合查询基本思路

我目前理解的流程：

```text
判断是否存在注入
        ↓
判断原查询列数
        ↓
UNION SELECT 对应列数
        ↓
判断页面回显位置
        ↓
把需要查询的数据放到回显位置
        ↓
继续获取数据库相关信息
```

例如：

```sql
UNION SELECT 1,database(),3
```

如果第二列可以回显，就可能看到当前数据库名称。

------

## 7. 当前学习理解

之前学习万能用户名时，重点是：

> 想办法改变原 SQL 的逻辑。

到了联合查询，我理解成：

> 不只是改变原 SQL 的判断条件，而是尝试在原查询后面追加一个自己的 `SELECT`，让数据库把我查询的结果一起返回。

所以联合查询的核心不是死记 Payload，而是：

**列数 → 回显位置 → 查询内容。**
