# SQL 注入读写文件

## 一、环境

- 靶场：自建本地 sqli-labs-master 靶场
- 工具：Burp Suite + HackBar
- 数据库：MySQL

## 二、什么是 SQL 注入读写文件

SQL 注入除了可以查询数据库中的数据，在满足一定权限和配置条件时，还可能利用数据库提供的文件操作功能：

```text
SQL 注入
   ↓
数据库文件操作
   ├── 读取服务器文件
   └── 写入服务器文件
```

所以 SQL 注入的影响不一定只停留在“读取数据库”。

## 三、读取文件

MySQL 常见的文件读取函数：

```sql
LOAD_FILE()
```

例如：

```sql
SELECT LOAD_FILE('/etc/passwd');
```

作用是尝试读取指定文件的内容。

在 Windows 环境中路径可能类似：

```sql
SELECT LOAD_FILE('C:/Windows/win.ini');
```

如果数据库有权限并且配置允许，就可能返回文件内容。

## 四、为什么 LOAD_FILE() 有时候读不到

执行：

```sql
SELECT LOAD_FILE('文件路径');
```

并不代表一定能成功。

常见原因：

- MySQL 进程没有文件读取权限
- `secure_file_priv` 限制了文件操作范围
- 文件路径错误
- 文件不存在
- 当前环境或数据库配置不允许读取

所以：

```text
LOAD_FILE()
      ↓
能否读取
      ↓
取决于权限 + 配置 + 文件路径
```

## 五、写入文件

MySQL 可以通过：

```sql
INTO OUTFILE
```

将查询结果写入服务器文件。

例如：

```sql
SELECT 'test' INTO OUTFILE '/tmp/test.txt';
```

执行后可能在服务器指定位置生成：

```text
test.txt
```

核心理解：

```text
SELECT 查询结果
       ↓
INTO OUTFILE
       ↓
写入服务器文件
```

## 六、写文件的限制

`INTO OUTFILE` 同样不是想写哪里就写哪里。

需要考虑：

- MySQL 运行账户的文件写权限

- `secure_file_priv`

  | 返回值                                         | 含义                                     |
  | ---------------------------------------------- | ---------------------------------------- |
  | 某个目录，例如 `C:\ProgramData\MySQL\Uploads\` | 文件操作通常只能在这个目录范围下         |
  | 空字符串 `''`                                  | 不限制目录（具体行为还要结合版本和权限） |
  | `NULL`                                         | 禁止通过这些功能进行文件导入/导出        |

- 目标目录是否存在

- 目标文件是否已经存在

- Windows / Linux 路径差异

尤其要注意：

**`INTO OUTFILE` 一般不能覆盖已经存在的文件。**

## 七、读写文件和 SQL 注入的关系

SQL 注入本身只是提供了：

```text
修改 SQL 语句的机会
```

真正实现文件读写，还需要数据库具备相应的：

```text
权限
+
配置
+
文件系统条件
```

所以不能简单理解成：

> “存在 SQL 注入，就一定可以读写服务器文件。”

正确理解是：

```text
SQL 注入
   ↓
能够执行相关 SQL
   ↓
数据库允许文件操作
   ↓
权限 / 配置满足
   ↓
才可能实现文件读写
```

## 八、读取文件和写入文件的区别

### 读取

主要使用：

```sql
LOAD_FILE()
服务器文件
   ↓
MySQL
   ↓
读取内容
   ↓
SQL 查询结果
```

## 九、我的理解

之前学习 SQL 注入时，主要是在想：

> “怎么把数据库里的用户名、密码查询出来？”

学习读写文件之后，可以发现 SQL 注入的影响范围更大。

如果数据库权限和配置允许：

```text
SQL 注入
   ↓
读取服务器文件
```

或者：

```text
SQL 注入
   ↓
向服务器写入文件
```

因此判断一个 SQL 注入漏洞的实际影响时，除了看能不能查询数据库，还需要考虑：

**数据库权限、文件权限以及 MySQL 文件操作配置。**

## 十、关键知识点

```text
SQL 注入读写文件
├── LOAD_FILE()      → 读取文件
├── INTO OUTFILE     → 写入文件
├── secure_file_priv → 文件操作限制
├── 数据库权限
└── 文件系统权限
```

核心记忆：

**SQL 注入读写文件 = 利用数据库的文件操作能力读取或写入服务器文件，但最终能否成功取决于数据库配置和权限。**
