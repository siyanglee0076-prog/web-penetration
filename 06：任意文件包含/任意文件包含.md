# 任意文件包含

## 1. 实验环境

- 靶场：自建本地 CMS 靶场（PHP + MySQL + Apache）
- 工具：BP（Burp Suite）+ HackBar
- 漏洞类型：文件包含

## 2. 什么是文件包含

PHP 中常见的文件包含函数：

```
include()
require()
include_once()
require_once()
```

如果程序把用户可控的参数直接放进包含函数：

```
include($_GET['file']);
```

那么用户就可能控制程序需要包含的文件，从而产生文件包含漏洞。

## 3. 基本思路

我测试文件包含时，主要按照：

```
找到文件包含参数
      ↓
确认参数是否可以控制
      ↓
尝试包含本地文件
      ↓
判断是否存在 LFI
      ↓
继续分析是否能够扩大利用
```

常见参数：

```
file=
page=
path=
include=
template=
```

参数名字本身不能直接判断漏洞，还是要看后端具体怎么处理。

## 4. 本地文件包含 LFI

LFI：

> Local File Inclusion，本地文件包含。

主要是尝试让程序包含服务器本地存在的文件。

例如：

```
?file=../../test.txt
```

其中：

```
../
```

表示返回上一级目录。

所以如果当前目录层级比较深，就可以尝试：

```
../../
../../../
../../../../
```

具体需要根据实际目录结构判断。

## 5. 为什么 LFI 经常和目录穿越一起出现

我之前容易把这两个漏洞当成一个东西。

现在理解为：

```
目录穿越
    ↓
改变文件路径
    ↓
找到其他目录 / 文件
    ↓
如果程序使用 include()
    ↓
可能形成 LFI
```

所以：

**目录穿越是一种路径控制方式，LFI 是文件包含造成的漏洞。**

## 6. LFI 和任意文件读取的区别

### 任意文件读取

主要是：

```
指定文件
   ↓
服务器读取
   ↓
返回文件内容
```

### 文件包含

主要是：

```
指定文件
   ↓
服务器加载文件
   ↓
交给当前程序处理
```

所以两者都可能出现：

```
../
```

但最终的漏洞行为并不一样。

## 7. 远程文件包含 RFI

RFI：

> Remote File Inclusion，远程文件包含。

如果服务器允许远程文件包含，程序可能加载远程位置的文件。

不过现在很多 PHP 环境默认会限制相关功能，所以实际环境中比 LFI 少见。

因此学习时目前主要先掌握：

**LFI → 本地文件包含**

## 8. 文件包含的测试重点

遇到类似代码：

```
include($_GET['file']);
```

重点关注：

```
参数是否可控
      ↓
有没有路径限制
      ↓
能否使用 ../
      ↓
能否包含本地文件
      ↓
包含的文件会如何处理
```

## 9. 当前学习理解

我现在对文件包含的理解：

> 文件包含不是简单地把文件内容读取出来，而是让当前 PHP 程序去加载用户指定的文件。

所以可以简单记成：

```
文件读取：
服务器帮我“读”文件

文件包含：
服务器帮我“加载”文件
```
