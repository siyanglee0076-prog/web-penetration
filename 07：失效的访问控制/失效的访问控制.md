# 失效的访问控制

## 1. 实验环境

- 靶场：自建本地 DVWA 靶场（PHP + MySQL + Apache）和 Vulhub（Docker 本地部署）
- 工具：BP（Burp Suite）+ HackBar
- 漏洞类型：失效的访问控制

## 2. 什么是失效的访问控制

访问控制主要负责：

> **判断当前用户有没有权限访问某个功能或资源。**

如果网站只判断：

```
用户有没有登录
```

却没有进一步判断：

```
这个用户有没有权限
```

就可能产生失效的访问控制。

## 3. 基本思路

我测试访问控制时，主要关注：

```
正常用户操作
      ↓
抓取请求
      ↓
修改 URL / 参数 / 请求方法
      ↓
观察是否还能正常访问
      ↓
判断是否绕过权限
```

简单来说就是：

> **本来我没有权限的东西，能不能通过修改请求直接访问。**

## 4. 常见测试方法

### ① 修改 URL

例如正常访问：

```
/user.php
```

发现管理员页面可能是：

```
/admin.php
```

普通用户直接访问：

```
/admin.php
```

如果没有权限校验，却可以正常进入，就可能存在访问控制问题。

### ② 修改参数

例如：

```
?id=100
```

尝试修改：

```
?id=101
?id=102
```

如果可以访问其他用户的数据，就可能存在越权。

### ③ 修改用户 ID

例如：

```
/user.php?id=100
```

当前登录的是用户 100。

修改为：

```
/user.php?id=101
```

如果能够直接查看用户 101 的信息，就可能存在：

> **水平越权**

## 5. 水平越权

水平越权：

> **相同权限等级的用户之间，可以访问彼此不应该访问的资源。**

例如：

```
用户A → 查看自己的订单
```

修改参数后：

```
用户A → 查看用户B的订单
```

权限等级没有发生变化，但访问了其他用户的数据。

可以简单理解成：

```
同级用户 → 访问其他同级用户资源
```

## 6. 垂直越权

垂直越权：

> **低权限用户访问了高权限用户才能使用的功能。**

例如：

```
普通用户
   ↓
访问管理员接口
   ↓
执行管理员操作
```

比如普通用户本来不能删除用户：

```
/admin/delete.php?id=10
```

但直接访问后却可以执行删除操作。

这就是典型的垂直越权。

## 7. 水平越权 vs 垂直越权

```
水平越权：

用户A
 ↓
访问用户B的数据
权限等级相同


垂直越权：

普通用户
 ↓
访问管理员功能
权限等级不同
```

记忆：

> **水平 = 同等级之间越权**

> **垂直 = 低权限访问高权限**

## 8. 测试重点

看到这些内容时可以重点关注：

```
?id=
?uid=
?user_id=
?order_id=
?file=
/admin/
/user/
/delete/
/update/
/edit/
```

尤其是：

```
修改 ID
修改 URL
直接访问后台接口
重复管理员请求
```

然后观察服务器有没有真正进行权限判断。

## 9. 当前学习理解

我现在对失效访问控制的理解是：

> **不是“能不能访问”，而是“当前这个用户有没有资格访问”。**

例如：

```
登录 ≠ 有权限
```

一个用户即使已经登录，也不代表他可以访问所有功能。

真正的访问控制应该判断：

```
当前用户是谁
      ↓
当前用户是什么权限
      ↓
当前资源属于谁
      ↓
当前用户是否有操作权限
```

### 本次遇到的问题

- 一开始容易把“登录验证”和“权限验证”当成一回事
- 后来发现登录成功只能说明身份被确认，不代表拥有所有权限
- 修改 `id` 可以用来测试水平越权
- 直接访问管理员接口可以用来测试垂直越权
- 最终判断漏洞的关键还是看服务器端有没有进行权限校验

### 最后总结

失效的访问控制核心：

```
找到需要权限的功能
        ↓
正常操作并抓包
        ↓
修改 URL / 参数 / 请求
        ↓
尝试访问其他用户资源或高权限功能
        ↓
判断是否存在水平 / 垂直越权
```

**核心记忆：**

```
水平越权：同级 → 同级

垂直越权：低权限 → 高权限
```
