# 不安全的反序列化

## 1. 实验环境

- 靶场：自建本地 CMS 靶场（PHP + MySQL + Apache）
- 工具：BP（Burp Suite）+ HackBar
- 漏洞类型：不安全的反序列化

## 2. 什么是序列化

序列化：

> **把对象转换成可以保存或传输的数据。**

例如 PHP 中：

```
serialize($data);
```

可以把对象转换成字符串。

反序列化：

```
unserialize($data);
```

再把字符串恢复成对象。

简单理解：

```
对象
 ↓
序列化
 ↓
字符串 / 数据
 ↓
反序列化
 ↓
对象
```

## 3. 什么是不安全的反序列化

如果程序直接对**用户可控的数据**进行反序列化：

```
unserialize($_GET['data']);
```

攻击者就可能构造特殊的序列化数据，让程序在反序列化过程中产生非预期行为。

因此核心问题是：

> **用户可以控制反序列化的数据。**

## 4. 基本思路

我测试反序列化时，主要关注：

```
找到可能的序列化数据
        ↓
判断数据是否可以被用户控制
        ↓
观察是否存在 unserialize()
        ↓
分析对象中的属性和方法
        ↓
寻找可利用的魔术方法
        ↓
判断最终能造成什么影响
```

## 5. PHP 常见魔术方法

PHP 反序列化中经常需要关注：

```
__construct()
__destruct()
__wakeup()
__toString()
__call()
__invoke()
```

其中比较重要的是：

### `__destruct()`

对象销毁时自动调用。

例如：

```
function __destruct() {
    // 某些危险操作
}
```

如果反序列化得到的对象能够触发相关方法，就可能产生漏洞。

## 6. 为什么魔术方法比较重要

正常情况下：

```
创建对象
    ↓
调用方法
    ↓
执行功能
```

但是反序列化时，程序可能自动触发某些魔术方法。

所以测试反序列化时，我会重点关注：

```
反序列化
   ↓
对象属性
   ↓
魔术方法
   ↓
危险函数 / 危险操作
```

## 7. 常见危险点

如果对象中的魔术方法最终调用了危险操作，就可能造成比较严重的影响。

例如：

```
文件操作
命令执行
数据库操作
代码执行
```

所以不能只看到：

```
unserialize()
```

就直接判断一定存在高危漏洞。

还需要继续分析：

```
用户是否可控
        ↓
能否构造对象
        ↓
能否触发魔术方法
        ↓
魔术方法中有什么操作
        ↓
最终能造成什么影响
```

## 8. 序列化数据的简单认识

PHP 序列化后的数据通常可以看到类似：

```
O:4:"User":1:{s:4:"name";s:3:"Lee";}
```

其中：

```
O
```

表示对象。

所以看到类似：

```
O:xxx:"xxx":
```

这种数据时，可以考虑是不是 PHP 序列化数据。

## 9. 当前学习理解

我现在对不安全反序列化的理解：

> **真正的问题不是“序列化”本身，而是程序把用户能够控制的数据直接反序列化，并且反序列化后的对象可能触发危险操作。**

所以核心可以记成：

```
用户可控数据
      ↓
unserialize()
      ↓
恢复对象
      ↓
触发魔术方法
      ↓
危险操作
      ↓
产生漏洞
```

### 本次遇到的问题

- 一开始容易认为看到 `unserialize()` 就一定存在反序列化漏洞
- 后来发现还需要判断反序列化的数据是否可控

- `__destruct()`、`__wakeup()` 等魔术方法是后续分析的重点
- 最终危害取决于魔术方法中是否存在可以利用的危险操作

      ↓

      ↓
分析对象
      ↓
寻找魔术方法
      ↓
分析危险操作
      ↓
判断最终危害
```

**核心记忆：**

```
反序列化 ≠ 一定有漏洞

用户可控
+
unserialize()
+
可利用的对象 / 魔术方法
=
可能存在不安全反序列化
