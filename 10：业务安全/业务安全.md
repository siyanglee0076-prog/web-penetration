# 业务安全

## 1. 实验环境

- 靶场：自建本地 CMS 靶场（PHP + MySQL + Apache）
- 工具：BP（Burp Suite）+ HackBar
- 漏洞类型：业务安全 / 业务逻辑漏洞

## 2. 什么是业务安全

业务安全主要关注：

> **程序本身的业务流程和规则是否可以被绕过。**

它和 SQL 注入、XSS 这种漏洞不太一样。

例如：

```
正常流程：

登录
 ↓
选择商品
 ↓
提交订单
 ↓
支付
 ↓
完成订单
```

如果攻击者可以通过修改请求，跳过其中某一步，就可能产生业务逻辑漏洞。

## 3. 基本思路

我测试业务安全时，主要关注：

```
正常操作
   ↓
抓取请求
   ↓
理解业务流程
   ↓
修改参数 / 请求顺序 / 请求次数
   ↓
观察服务器是否严格校验
   ↓
判断能否绕过业务规则
```

核心不是找某个固定 Payload，而是：

> **理解正常业务应该怎么运行，再想办法破坏这个流程。**

## 4. 常见业务安全问题

### ① 参数篡改

例如：

```
price=100
```

尝试修改为：

```
price=1
```

如果服务器直接相信客户端提交的价格，就可能导致业务逻辑问题。

### ② 数量 / 金额修改

例如：

```
num=1
```

修改：

```
num=0
num=-1
```

观察服务器是否进行了合理性判断。

金额参数同样需要关注：

```
price=
amount=
money=
```

### ③ 验证码绕过

正常流程：

```
输入验证码
 ↓
服务器验证
 ↓
继续操作
```

测试时可以关注：

```
验证码是否真正校验
是否可以重复使用
是否存在有效期问题
是否可以绕过验证接口
```

### ④ 重放请求

正常情况下，一个操作可能只能执行一次。

例如：

```
提交订单
 ↓
获得优惠
```

如果把同一个请求重复发送多次：

```
第一次 → 成功
第二次 → 仍然成功
第三次 → 仍然成功
```

就需要考虑服务器是否缺少重复提交限制。

### ⑤ 业务流程绕过

例如正常流程：

```
注册
 ↓
实名认证
 ↓
绑定手机号
 ↓
提现
```

如果直接请求提现接口：

```
/withdraw
```

服务器仍然执行提现，就可能存在业务流程校验问题。

## 5. 越权和业务安全

业务安全中也经常遇到权限相关问题。

例如：

```
用户A
 ↓
修改 user_id
 ↓
操作用户B的数据
```

这种情况可能属于：

> **水平越权**

而：

```
普通用户
 ↓
直接调用管理员功能
```

则可能属于：

> **垂直越权**

所以业务安全和前面学习的**失效的访问控制**也有一定联系。

## 6. 业务安全测试重点

看到这些参数时，可以重点关注：

```
id=
uid=
user_id=
price=
amount=
money=
num=
discount=
coupon=
status=
role=
```

同时关注：

```
请求次数
请求顺序
业务状态
身份状态
金额计算
优惠逻辑
验证码
```

## 7. 当前学习理解

我现在对业务安全的理解：

> **业务安全的核心不是“程序有没有某个漏洞函数”，而是服务器有没有正确执行业务规则。**

例如：

```
客户端：
“我要买 10 个，价格 1 元。”
```

服务器不能直接相信客户端的数据，而应该自己判断：

```
商品价格是多少？
购买数量是否合法？
用户有没有优惠资格？
订单有没有支付？
这个操作是不是已经执行过？
```

所以：

> **凡是客户端可以提交的关键业务数据，都不能直接信任。**

### 本次遇到的问题

- 一开始认为业务安全就是修改参数
- 后来发现参数篡改只是其中一种方式
- 真正重要的是先理解完整业务流程
- 需要关注请求顺序、请求次数、参数值和业务状态
- 业务安全往往需要结合实际功能进行分析，而不是套固定 Payload

### 最后总结

业务安全核心：

```
理解正常业务流程
        ↓
抓取正常请求
        ↓
修改参数 / 顺序 / 次数
        ↓
观察服务器校验
        ↓
尝试绕过业务规则
        ↓
判断是否产生异常业务结果
```

**核心记忆：**

```
技术漏洞：
程序哪里写错了？

业务漏洞：
程序有没有正确执行业务规则？

```
